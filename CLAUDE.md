# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

GoatTracker v2 (2.77): a tracker-style Commodore 64 / SID music editor written in C (plus some C++ for the SID emulation). It is being ported to a GTK4/libadwaita UI (Linux only; the Win32 and MorphOS builds were dropped), with SDL2 used only for audio. Licensed under the GPL. The repository is on GitHub at robcowell/goattracker (private); its first commit is the unmodified 2.77 source. Old Windows `.exe` binaries are still checked in under `win32/`.

`readme.txt` is the authoritative user and format documentation: keyboard commands, song data semantics, the `.SNG`/`.INS`/sound-effect file formats (section 6), and the version history. It is Latin-1 encoded, so read it with `iconv -f latin1 -t utf8 readme.txt`.

## Building

All builds run from `src/`. There is no test suite. Verify changes by building and then loading or playing the example songs in `examples/` (`.sng`, `.ins`).

```sh
cd src && make              # binaries go to ../linux/ (also builds the bme/ host tools)
make clean
make install                # copies the binaries to /usr/local/bin and the man page to /usr/local/man/man1
```

- Requires `libgtk-4-dev`, `libadwaita-1-dev`, `libsdl2-dev` and `libasound2-dev` (ALSA, for MIDI input). `makefile` sets the flags and includes `makefile.common`, which defines `ENGINE_OBJS` (shared by `goattrk2` and `gt2reloc`) and `GUI_OBJS` (the `gtk*.c` files, the only ones compiled with GTK flags).
- Testing GUI changes without touching the user's desktop: run on a nested display (`Xephyr :5`) with `GDK_DEBUG=no-portals` so file dialogs open on that display instead of via the desktop portal, and point `HOME` at a scratch directory so `~/.goattrk/goattrk2.cfg` isn't overwritten on exit. Drive it with `DISPLAY=:5 xdotool` and capture with `xwd -root` + `ffmpeg`. Without a window manager, call `xdotool windowfocus` before sending keys. Avoid metacity in Xephyr: it swallows clicks into the window content and hides popovers.
- Engine-level checks without the GUI: a throwaway program can `#define main gt2reloc_main` and `#include "gt2reloc.c"` to get all the engine globals, then call `loadsong()`, `savesongfile()` and so on. Link it against the engine objects with SDL2. `songfilename` is only 60 bytes, so use bare file names in the current directory.

## Architecture

**Embedded data file.** Runtime assets are packed into `goattrk2.dat` according to the list in `goattrk2.seq`: the 6502 playroutines `player.s` and `altplayer.s`, plus the font, palette, cursors and icon. `dat2inc` then turns that into `goatdata.c` as the C array `datafile[]`. The `bme_io` layer (`io_open` and friends) reads files from this embedded blob. **If you edit `player.s`, `altplayer.s`, or any `.bin` asset, regenerate `goattrk2.dat` and then `goatdata.c`.** The makefile rules do this, but stale checked-in `.o` files can hide the change, so run `make clean` when in doubt.

**GTK user interface.** Everything runs on GTK's main thread (audio runs in SDL's callback thread, as it always did). `gtkui.c` holds `main()`: it calls `goattrk2_init()` (config, command line, SDL audio, initial song; returns an exit status for things like `-?`), builds a single docked window, and calls `goattrk2_shutdown()` (stop sound, save config) on quit. The UI keeps no copy of the editor state: it draws and edits the engine's globals (`epchn`, `eppos`, `einum`, `editmode`, ...).
- `gtkui.c`: window layout (orderlist | pattern | instrument column, tables and song info below), toolbar, menus, status bar, the 20 ms tick that drives follow-play and redraws during playback, and keyboard routing. Keys on the grids are translated to the engine's key codes and fed through `runkey()` → `docommand()`, so every classic key command still works. Keys stay with GTK while a text field, dialog or menu has focus (function keys excepted). Focusing a panel sets `editmode`, and `ui_focuseditmode()` moves focus when a command changes it.
- `gtkgrid.c`: the pattern, orderlist and table editors as custom-drawn `GtkDrawingArea`s (Pango monospace font, tracker colours). The orderlist is drawn vertically, so `orderlistcursor()` in `gtkui.c` rotates the arrow keys. Mouse handling: a drag gesture places the cursor and sets the engine's mark variables (`epmark*`, `esmark*`, `etmark*`); right-click opens a `GtkPopoverMenu` whose items run classic keys through `ui_runkey()` (see the `GRIDITEM` tables). View model: keyboard input, follow play and undo call `grid_followcursor()`, which keeps the pattern and orderlist centred on the cursor; mouse clicks, drags and the wheel switch that off so the view stays put under the pointer.
- `gtkpanels.c`: instrument list (with the Shift+X/C/V/S/Del commands) and the native instrument editor; song name/author/copyright entries. Song and instrument names are Latin-1; convert with `ui_toutf8()`/`ui_fromutf8()`.
- `gtkdialogs.c`: implements the hooks in `gui.h` that the engine's command handlers call (`ui_quit`, `ui_clear`, `ui_help`, `ui_editadsr`, `ui_relocator`, `ui_load`, `ui_save`) with non-blocking libadwaita dialogs and `GtkFileDialog`. The engine must never block waiting for input.
- Key codes (`KEY_xxx` in `bme/bme_main.h`) are the ASCII value of the unshifted character, or `BME_XKEY(keysym)` (256 + the low byte of the X11/GDK keysym). They must stay below `MAX_KEYS` (512).
- Packer options beyond stock: `packplayorder` (patterns numbered by first appearance in the orderlists; `gt2reloc -Q1`) and `PLAYER_ZPPLAYSID` (the `ZPPLAYSID` conditional in `player.s`/`altplayer.s`, which copies the zeropage ghostregs to the SID each frame; `gt2reloc -K1`). Both are off by default; keep the default output byte-identical to stock.
- The packer (`greloc.c`) has a single batch path for both programs: options come from globals (`playerversion`, `playeradr`, `zeropageadr`, `fileformat`), the output file from `packedsongname`, and messages go to `STDOUT`/`STDERR`, which the editor points at a memory stream (`relocout`) and shows afterwards. `relocsuccess` reports the outcome.
- Undo/redo and unsaved-changes tracking (`gundo.c`) work by comparison rather than per-command instrumentation: after each action the UI calls `undo_checkpoint()`, which compares the song data block by block (instruments, tables, names, each subtune's orderlists, each pattern) with a shadow copy and stores the changed blocks' old contents. Anything new that edits song data only needs a checkpoint after it; pass a nonzero coalesce key to merge repeated edits of one field. Loading a song calls `undo_reset()`; saving calls `undo_marksaved()`, and `undo_isdirty()` drives the "•" in the title and the save/discard prompt (`ui_confirmdiscard()`). Ctrl+Z/Ctrl+Y are taken before the classic key handlers, where Ctrl otherwise acts as Shift.
- `gtkinfo.c` turns the item under the cursor into a plain-language description for the status bar (`info_describe()`). Its table decoder (`table_describe()`, with a brief form) follows readme §3.2–3.4. The brief form fills the tables' description column (View → Describe Table Rows). `table_isreachable()` follows instrument pointers, pattern commands and wavetable commands through the tables, so rows nothing can execute are drawn dimmed; it is cached by `undo_version()`.
- When RETURN (or an instrument editor table button) moves to another editor, `runkey()` pushes the old cursor (`ui_pushplace()`), and Alt+Left (`ui_goback()`) returns to it.
- Text size (View → Larger Text, `-w`): `grid_setfontscale()` sets the grids' own Pango font size and calls `ui_settextscale()`, which puts a `gt-textsize-N` CSS class on the window. Font size inherits in GTK CSS, so every native widget, menu, popover and dialog scales with it; libadwaita styles with fixed sizes (`heading`, `caption`, popover contents) are restated relative to it. Custom-drawn parts follow through `monitor_setscale()` and `panels_setscale()`. The text size itself is the stock `bigwindow` setting in `goattrk2.cfg`. The window's size, maximized state and the four `GtkPaned` divider positions (`panes[]`) are saved in `gtkedition.ini` (`[window]`, with the text size they were saved at); `setdefaultsize()` restores them at startup, or uses 1280x820 the first time, scaled if the text size differs and capped to the first monitor. It maximizes only after the window is first mapped, because some window managers otherwise restore it smaller; changing the text size later scales the dividers (`scalepanes()`: the side of each `GtkPaned` that doesn't resize with the window, such as the instrument column, tables, orderlist and instrument list, is scaled and the other side takes the rest) and resizes the window by the ratio (`resizefortext()`), capped to its monitor but remembering the uncapped size so shrinking again returns to where it started.
- Settings of this edition (not in stock GoatTracker) live in `~/.goattrk/gtkedition.ini` (`GKeyFile`, `loadsettings()`/`savesettings()` in `gtkui.c`). Don't append to `goattrk2.cfg`: it ends with string values that may be blank, and `getparam()` skips blank lines, so anything appended would be read into the wrong field.
- Song files: `savesongfile(path)` saves anywhere without touching the current song's name (used by backups); `savesong()` wraps it. Both write GoatTracker Ultra's trailing chunks (`0x1F` editor settings, `0x9A` instrument pans if a GTUltra song supplied them, `0x9B` SIDTracker64 flag), and `readsongchunks()` applies them on load (`songsettingsloaded`). Stock 2.77 stops reading after the patterns, so the chunks are invisible to it. `validatesongfile()` (GTS2-GTS5) and `validatev1songfile()` (GTS!) check a file's counts and lengths against the array sizes before `loadsong()`/`mergesong()` touch any data (`loadresult`, `mergeresult`), which also identifies 6-channel GoatTracker Stereo/Ultra songs. Song files are read into memory once (`opensongfile()`, via `fmemopen`) so the check and the load see the same bytes even if the file changes on disk. After loading or merging, `maskpatterninstruments()` keeps pattern instrument bytes below `MAX_INSTR`.
- Offline rendering (`grender.c`, engine side): `render_begin()` pauses the SDL audio device and stops live playback, then `render_run()` calls `playroutine()` once per frame and `sid_fillbuffer()` for that frame's samples, as the audio callback does. A render ends when every channel has looped (`songloops[]`, counted in `gplay.c`'s sequencer), the song stops, or a time limit passes. A silent mode skips the SID emulation, which `render_songlength()` uses for the status bar. `render_end()` resets the SID and resumes audio. WAV export (`gtkwav.c`) renders in idle-callback chunks into memory, then applies fade and normalisation and writes the file.
- Line endings: all text files use LF, enforced by `.gitattributes` (the original 2.77 sources were mostly CRLF and were converted in one commit). `goattrk2.dat` and `goatdata.c` embed `player.s`/`altplayer.s` byte for byte, so they are regenerated whenever those change.
- Help text lives in `ghelp.c` as a section table (`gethelpsections()`) rendered by `ui_help()`.
- `gtkinput.c`: polyphonic jam voices (`jam_noteon()`/`jam_noteoff()`, keyed by a raw key code or a MIDI note) and MIDI input from the ALSA sequencer, polled with `g_unix_fd_add()`. In jam mode `onkeypressed()` sends note keys (`pattern_notekey()`) to it, and a `key-released` handler stops them; in edit mode MIDI notes go through `pattern_enternote()`, the same code typed notes use.
- `gtkmonitor.c`: the piano keyboard (bottom bar) and SID register panel (under the pattern editor). Both read the `sidreg[]` shadow from `monitor_update()`, which the 20 ms tick calls. The register panel sits in a horizontally scrolling pane so larger text never widens the window.
- Editor-only playback features live in `gplay.c` and are switched off for offline renders: `loopplay` (the sequencer repeats each channel's pattern), `looprowstart`/`looprowend` (F3 with marked rows; any `initsong()` clears them), and `seqpos[]`/`seqcount[]` (which orderlist entry each channel last started). `render_seek()` in `grender.c` uses those to run the playroutine silently from the song start to an orderlist position for Play from Here.
- Live-only sound settings: `mastervolume` scales the output in `sound_mixer()`; `sid_setdetune()` scales the clock both reSID and `sid_fillbuffer()` use, so pitch changes and samples per frame don't (call it with the audio locked, via `ui_setdetune()`). Settings of this edition (view toggles, volume, detune, auto-next pattern, backups) are saved in `~/.goattrk/gtkedition.ini`.

**Editor (`goattrk2`).** `goattrk2.c` holds `goattrk2_init`/`goattrk2_shutdown`, the config, the global editor state (declared `extern` in `goattrk2.h` under `#ifndef GOATTRK2_C`) and `docommand()`, which dispatches a keypress on `editmode` (`EDIT_PATTERN`, `EDIT_ORDERLIST`, `EDIT_INSTRUMENT`, `EDIT_TABLES`, `EDIT_NAMES`). Each subsystem lives in its own `g*.c` file:
- `gsong.c`: song data model (orderlists, patterns, instruments, the wave/pulse/filter/speed tables), plus `.sng`/`.ins` load and save and v1 import.
- `gpattern.c`, `gorder.c`, `ginstr.c`, `gtable.c`: the editors for each data type.
- `gplay.c`: the in-editor playroutine. It is a C reimplementation that must stay behaviourally in sync with the 6502 `player.s`/`altplayer.s`.
- `greloc.c`: packer/relocator. It emits the song data as assembler source, prepends the chosen playroutine, assembles it with the built-in 6510 cross-assembler in `asm/` (taken from Exomizer), and writes PRG/BIN/SID output.
- `gsound.c` / `gsid.cpp`: audio output. `gsid.cpp` picks between reSID (`resid/`) and reSID-fp (`resid-fp/`) at runtime, and also handles the HardSID and Catweasel hardware paths (Windows-specific code still sits behind `#ifdef __WIN32__` but is no longer built). Hardware SID output is driven by an SDL2 timer (`SDL_AddTimer`); emulated output by the SDL2 audio callback in `bme/bme_snd.c`.
- `gdisplay.c` (note names, song timer, `followplayupdate()`), `gfile.c` (paths, `editstring()`), `ghelp.c` (help text). File loading works on a bare file name in the current directory, so the UI `chdir`s to the chosen folder first.
- `gcommon.h`: shared constants, including pattern command numbers, data limits (`MAX_PATT`, `MAX_INSTR`, ...), orderlist and pattern byte encodings, and the `INSTR` struct.

**`bme/`** is what remains of a small Covert BitOps library: SDL2 audio (`bme_snd.c`), the embedded data file reader (`bme_io.c`), endianness helpers, and the key code definitions.

**`gt2reloc`** is the command-line packer. `gt2reloc.c` `#define`s `GT2RELOC` and `#include`s `greloc.c` directly, and links `ENGINE_OBJS` (no GTK). It defines its own copies of the editor globals the shared modules reference.

**Standalone utilities** (`ins2snd2.c`, `sngspli2.c`, `mod2sng.c`) are single-file tools that link only `bme_end.o`, which handles endianness.

When changing song format semantics, keep `gsong.c` (load/save), `gplay.c` (editor playback), `player.s`/`altplayer.s` (C64 playback), `greloc.c` (packing), and readme section 6 consistent.
